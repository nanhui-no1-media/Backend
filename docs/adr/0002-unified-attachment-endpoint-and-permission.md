# 统一附件端点 + 抽象权限规则（option iii）

附件上传 / 删除收口为**单一端点** `POST /attachments/`（及 `DELETE /attachments/{id}/`），请求体带 `task_id` 或 `proposal_id` 之一。不再保留 `/tasks/{id}/add_attachment/`、`/proposals/{id}/add_attachment/` 两个父级动作。

权限用**一条抽象规则**统一，父级差异收进 helper，不拆成两个类：

> 操作者须为该父级的**创建者**，或该父级的**活跃参与者**，或持有该父级**管理权限**者。

- 任务：活跃参与者 = 进行中（`in_progress`）时的负责人 / 协作者；管理权限 = `tasks.manage_tasks`。
- 申报：活跃参与者 = 空（创建者即唯一参与者）；管理权限 = `proposals.change_proposal`。

新增与删除沿用同一套规则。

## 被否的方案

- **按父级分动作（A）**：模型统一、HTTP 仍分两个端点。零回归、权限原样保留，但与"独立成一个子系统"的字面目标不符；用户已明确要统一入口。
- **全面取消附件权限**：最省事，但任意成员可删任意人附件——投票中删申报材料、待验收删交付物等敞口不可接受。权限分支的复杂度源自领域（任务本就有协作者与进行中状态），删权限只是无视它、并未消除。
